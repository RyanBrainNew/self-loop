01

Router 拥有状态。Worker 只写 Attempt，Verifier 只写证据。

Agent 能写代码。
它不能证明代码该合并。

self-loop 不把“完成”当成 worker 的自我汇报。每个交付都要经过独立的 clean worktree 验证，再由人决定是否合并。

authority human merge gate

从可执行，到可审查。

每一步都有明确的所有者和落盘证据。失败会消耗一次 Attempt；超过上限就阻塞， 等 `router recover`，而不是无限重试。

  1. 选择与领取

    只看符合策略的 issue，跳过已有 open PR 的工作，用 TTL 防止重复领取。

    .loop/triage.json policy: ready-for-agent

  2. 绑定上下文

    生成 Task Card 和 Context Packet。验收标准缺失时，先阻塞，不猜。

    task-card.md context packet

  3. 执行一次 Attempt

    Worker 在分支上实现并开 PR。它拥有代码，不拥有 Ticket 状态。

    result.json one branch, one PR

  4. 独立验证

    Verifier 不信任 worker 的报告，在干净 worktree 中复跑项目门禁。

    verification.jsonl pass / fail / human_review

  5. 交给人类

    Issue 收到幂等状态评论，PR 附上证据。合并权始终留在人手里。

    pull request never auto-merge

在你已有的地方运行。

核心只依赖 Node、git 和 GitHub API。`--repo` 指向目标仓库； cron、CI 和编排器都只是调用同一条命令。

terminal node "$SKILL_DIR/scripts/run.mjs" router tick --repo "$TARGET" 手动或事件唤醒；默认 1 条
inbox router post --type issue --ticket 42 && router tick 事件驱动，可配并发
cron */15 * * * * node .../run.mjs router tick --repo /srv/project 确定性调度
CI SELF_LOOP_REPO=$GITHUB_WORKSPACE node .../run.mjs router tick 临时 runner 也能跑
Orca adapters/orca/setup.mjs --repo "$TARGET" 可选适配器

Orca 只负责它擅长的调度和 worktree；核心脚本不依赖它。 外部编排器接管 worktree 时，设置 router.worktreeMode: "external"。
